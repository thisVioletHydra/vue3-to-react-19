# Context — это не Pinia и не Query

## В чём проблема (по-нормальному)

Во Vue `provide` / `inject` — прокинуть значение вниз без цепочки props. В React то же самое называется **Context**.

Context делает ровно одну вещь: **пробрасывает значение по дереву компонентов**. Родитель кладёт значение в `Provider`, любой потомок читает через `useContext`. Всё.

Он **не** умеет сам:
- кэшировать ответы API (это TanStack Query);
- быть глобальным стором с экшенами как Pinia/Zustand;
- умно обновлять только тех, кому кусок данных нужен (любой `setState` у провайдера часто дёргает **всех** подписчиков Context).

Фраза «это канал, не кэш и не стор» значит: Context = **труба доставки** значения вниз. Не склад товаров с сервера. Не корзина с `addItem`.

## Как не делать

- Список товаров / ответ API положить в Context «чтобы не прокидывать props» — получишь лишние ререндеры и ручной loading. Для этого Query.
- Корзину на 8 уровней вниз через Context вместо Zustand — боль.
- Считать Context заменой Pinia на собесе.

## Как надо

| Что | Куда |
| --- | --- |
| Тема dark/light, локаль `ru`/`en` | Context — редко меняется, нужно далеко |
| «Кто залогинен» как факт сессии | Context или тонкий session-store |
| Список с API | TanStack Query |
| Корзина, сайдбар открыт | Zustand |

На собесе коротко: «Context — provide/inject. Pinia у меня в React = Zustand. Серверные данные = Query.»
