# shared/ — код без бизнес-смысла

Сюда попадает то, что вообще ничего не знает про товары, логины и админки.
Проверка простая: можно скопировать файл в другой проект (интернет-магазин,
CRM, что угодно) — и он там заработает без правок? Тогда это shared.

## Примеры того, что сюда поедет

- кнопка / инпут из будущего ui-kit (`shared/ui/Button.tsx`)
- хелпер форматирования денег (`shared/lib/formatMoney.ts`)
- настроенный http-клиент (`shared/api/client.ts`)
- общие константы

## Примеры того, что сюда НЕ поедет

- карточка товара — знает, что такое товар → `entities/product`
- форма логина — знает про логин → `pages/login`
- сайдбар админки — знает про админку → `app/layouts`

## Почему shared внизу иерархии

Shared может импортировать только shared. Если кнопка из ui-kit вдруг
импортирует «товар», то кнопку больше нельзя использовать без товара —
и весь смысл общего кода умер. Поэтому направление всегда одно:
все слои могут брать из shared, shared не берёт ни у кого.

Пока папка пустая — первый жилец появится, когда один и тот же кусок
кода понадобится в третьем месте и надоест копипастить.
