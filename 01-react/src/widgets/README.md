# widgets/ — что это за папка

Сейчас она пустая, и это нормально. Объясняю, зачем она вообще существует.

## Проблема, которую решают widgets

Смотри на будущую страницу каталога. На ней будет:

- поле поиска (это feature `search-products`)
- сетка карточек товаров (карточка — это entity `product`)
- форма добавления (это feature `add-product`)

Кто-то должен склеить поиск и сетку вместе: держать стейт запроса, фильтровать
товары, отдать результат карточкам. Вопрос: где живёт этот склеивающий код?

Вариантов два:

1. Прямо в странице (`pages/catalog`). Так и делаем сейчас.
2. В отдельном блоке-виджете (`widgets/catalog-grid`). Так делают, когда
   страница разжирела или когда этот же блок нужен на второй странице.

## Правило, когда заводить widget

Простое правило: **пока блок нужен только одной странице — держи его в этой
странице.** Не выноси заранее «на всякий случай».

Выноси в widgets, когда случилось одно из двух:

- этот же блок понадобился на второй странице (например, та же сетка товаров
  и в каталоге, и на главной);
- страница стала нечитаемой простынёй, и хочется разбить её на крупные
  именованные куски.

## Аналогия с Vue

Если в твоём Vue-проекте были компоненты типа `TheSidebar.vue`,
`ProductListSection.vue` — крупные блоки, которые сами состоят из мелких
компонентов, но ещё не целая страница — вот это и есть widgets.

## Итог одной строкой

Widget = крупный кусок интерфейса, собранный из нескольких фич и entities,
но меньше целой страницы. Пока такого куска нет — папка пустая, и трогать её
не надо.
