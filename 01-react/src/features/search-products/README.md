# features/search-products — действие «найти товар»

Поле поиска. Полностью контролируемое: значение живёт НЕ здесь, а у
родителя. Феномен «v-model наоборот»:

- родитель передаёт `value` (текущий запрос)
- поле на каждый ввод зовёт `onChange(новый текст)`
- родитель сам решает, что с этим делать (фильтровать список)

## Почему фильтрация не здесь

Поле не знает, что оно фильтрует. Ему без разницы — товары, юзеры,
заказы. Поэтому его можно переиспользовать где угодно. Логика «отфильтруй
товары по запросу» живёт у владельца списка товаров (сейчас App, потом
CatalogPage).
