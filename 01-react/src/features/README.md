# features/ — действия пользователя

Feature = одна вещь, которую пользователь **делает**. Не «кусок интерфейса
вообще», а именно действие: добавить товар, найти товар, выйти из аккаунта.

## Что здесь лежит

| папка | действие пользователя |
|---|---|
| `add-product` | заполнил форму → появился новый товар |
| `search-products` | ввёл текст → список отфильтровался |

## Как отличить feature от entity

Вопрос: тут описано **что юзер делает** или **что это за штука**?

- «Форма добавления товара» — юзер делает. Feature.
- «Карточка товара: название, цена, описание» — это описание штуки,
  никакого действия. Entity.

Кнопка «В список» внутри карточки не ломает правило: карточка просто
кричит наверх «по мне кликнули» через колбэк `onAddToList`. Что делать
с этим кликом — решает страница. Карточка сама ничего не добавляет.

## Как отличить feature от page

Вопрос: выживет ли этот кусок без URL?

Форму добавления товара можно показать где угодно: на странице каталога,
в модалке, в сайдбаре. Ей всё равно, какой сейчас адрес в браузере.
Значит feature. А «страница логина» без адреса `/login` бессмысленна —
значит page.

Отсюда правило: **feature не знает про роутер**. Внутри `add-product`
не должно быть `useNavigate` или «если мы на /catalog». Если фиче
нужно «после успеха перейти на другую страницу» — она зовёт колбэк,
а переход делает страница.

## Почему export named, а не default

Default нужен страницам ради `React.lazy`. Фичи отдельно не грузят —
они приезжают в том же чанке, что и страница, которая их использует.
Так что обычный named export: `export function AddProductForm() {…}`.
