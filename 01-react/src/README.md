# src/ — как устроен проект (FSD)

FSD (Feature-Sliced Design) — способ раскладывать код не «по типу файла»
(components, utils, views), а «по смыслу»: это экран? это действие юзера?
это бизнес-сущность?

## Слои сверху вниз

```
app        сборка приложения: роутер, layout'ы, глобальные стили
pages      экраны, у каждого свой URL: /login, /catalog, 404
widgets    крупные блоки из нескольких фич (пока пусто)
features   одно действие пользователя: «добавить товар», «поиск»
entities   бизнес-сущности: что такое «товар», как выглядит его карточка
shared     код без бизнес-смысла: кнопки, хелперы, http-клиент (пока пусто)
```

## Главное правило: импорты только вниз

Слой может импортировать только из слоёв **ниже** себя:

- `pages/catalog` имеет право взять `features/search-products` и
  `entities/product` — они ниже.
- `entities/product` НЕ имеет права импортировать из `pages` — это вверх.
  Если карточка товара знает про страницу каталога, значит карточку уже
  нельзя использовать нигде, кроме каталога. Это и есть спагетти.

Зачем это надо: когда каждый файл может импортировать любой другой, через
месяц проект превращается в клубок, где нельзя тронуть одно, не сломав пять.
Правило «только вниз» делает зависимости предсказуемыми.

## Как устроена папка внутри слоя (слайс)

```
pages/login/
  index.ts     единственный вход снаружи («public API»)
  README.md    зачем этот слайс
  ui/          компоненты (JSX)
  model/       появится позже: стейт, схемы валидации этой страницы
```

Снаружи импортируй только через `index.ts`:

```ts
// правильно
import { LoginPage } from "../pages/login";

// неправильно — залез внутрь чужого слайса
import LoginPage from "../pages/login/ui/LoginPage";
```

Зачем: `index.ts` — это дверь. Всё, что не экспортировано через дверь,
можно спокойно переделывать внутри слайса, не боясь сломать полпроекта.

## Аналогия с Vue

В типичном Vue-проекте у тебя было `views/` (страницы), `components/`
(всё подряд), `stores/` (Pinia). FSD — это то же самое, только `components/`
разрезан по смыслу: карточка товара → entities, форма поиска → features,
сайдбар → widgets. А стор, когда появится, будет жить внутри слайса,
которому принадлежит (`entities/product/model`), а не в общей куче.
