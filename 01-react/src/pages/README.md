# pages/ — экраны приложения

Одна папка = один экран = один URL. Это аналог `views/` во Vue-проекте.

## Что здесь лежит

| папка | URL | что это |
|---|---|---|
| `login` | `/login` | экран входа |
| `catalog` | `/catalog` | экран каталога (пока пустой, перенесёшь из App) |
| `not-found` | `*` | экран «такой страницы нет» |

## Как понять, page это или не page

Задай вопрос: «могу я дать этому куску собственный адрес в браузере?»

- Экран логина — да, `/login`. Это page.
- Форма поиска — нет, она не живёт по своему адресу, она часть каталога.
  Это feature.
- Сайдбар — нет, он висит на всех страницах админки сразу. Это layout
  (или widget, если разжиреет).

## Чем page занимается, а чем нет

Page — это **склейка**: взять фичи и entities, расставить по экрану,
подержать общий стейт экрана. Страница каталога возьмёт поиск из
`features/search-products`, карточки из `entities/product` и соединит их.

Page НЕ содержит: роутер (он в `app/router.tsx`), рамку с сайдбаром
(она в `app/layouts`), переиспользуемые кнопки (они в `shared`).

## Почему у страниц export default

`React.lazy` — ленивая загрузка чанка страницы — требует, чтобы модуль
имел `default` export. Поэтому договорённость: компонент страницы
экспортируем как default. Подробности с примерами — в `app/router.tsx`.
